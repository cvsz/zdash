# zDash v0.42.0-rc3

Release candidate date: 2026-08-23

## Purpose

This release candidate consolidates the mission-control dashboard modernization with post-upgrade dependency, supply-chain, runtime, and release hardening.

## Dashboard and frontend

- Mission-control navigation groups and dashboard information architecture v2.
- React 19, React Router 7, Recharts 3, Vite 8, TypeScript 7, Vitest 4, and Tailwind CSS 4.
- Node 24 LTS is the canonical frontend/CI runtime.
- Strict npm dependency resolution replaces the legacy peer-dependency bypass.
- ESLint flat configuration is added for the TypeScript/React source tree.
- Generated TypeScript build state is no longer tracked.

## Backend and authentication

- FastAPI/Pydantic/SQLModel/SQLAlchemy/Alembic dependency baseline refreshed.
- JWT signing and validation migrate from `python-jose` to PyJWT while preserving HS256 payload, expiry, role, access-token, refresh-token, and fail-closed invalid-token behavior.
- Reproducible runtime/development dependency locks are generated and audited before release acceptance.

## Supply-chain security

- Weekly Dependabot updates cover npm, pip, GitHub Actions, and Docker.
- CodeQL scans Python and JavaScript/TypeScript.
- Dependency Review blocks newly introduced high-severity dependency findings.
- Python and npm audits are intended to become blocking once the refreshed locks are accepted.
- The vulnerable `ecdsa` dependency chain is removed from the JWT runtime rather than suppressed.

## Runtime and containers

- Node 24 is standardized across CI, Pages, release workflows, and frontend builders.
- NGINX is on the 1.30.4 Alpine line.
- PostgreSQL is pinned to 16.15 for this candidate.
- Redis is updated to 8.2.8.
- Prometheus is updated to 3.14.0.
- Production database, Redis, and Prometheus host ports bind to loopback only.
- `no-new-privileges` is enabled for production containers where supported by the Compose deployment.

## PostgreSQL major-version boundary

PostgreSQL 18.6 is evaluated separately. No production 16 → 18 major migration is included in rc3. The migration requires a successful backup restore, extension inventory, Alembic verification, tenant/auth/e2e regression, and an exercised rollback before a dedicated database migration PR can be accepted.

See `docs/operations/postgresql-major-upgrade-plan.md`.

## Safety invariants

The candidate does not relax the existing safety defaults:

- `DRY_RUN=true`
- `LIVE_TRADING_ACK=false`
- `MT5_ENABLED=false`
- `PRODUCTION_ALLOW_LIVE_ACTIONS=false`
- `RISK_GUARDIAN_ENABLED=true`
- social and IoT mutation remain approval/dry-run gated by default
- auth/RBAC and tenant isolation remain fail-closed

## Required release evidence

Do not tag rc3 until the exact candidate head has passed:

- backend Ruff, mypy, pytest, and Alembic checks;
- frontend TypeScript, ESLint, Vitest, and production build;
- CodeQL and dependency review;
- blocking Python/npm dependency audits;
- Docker image builds and production Compose validation;
- PostgreSQL-backed e2e migrations, auth bootstrap/login, and API envelope smoke tests;
- release candidate artifact/SBOM generation.

The final release notes must record the exact validated commit SHA and workflow results.
